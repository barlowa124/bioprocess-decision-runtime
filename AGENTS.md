# Project Guidance

- Keep all process data and scenarios synthetic and public-safe.
- Do not claim GMP compliance, regulatory acceptance, process validation, or patient-safety assurance.
- Treat policy values as illustrative unless supplied and approved through a documented scientific process.
- Preserve advisory-only behavior; do not add equipment actuation without an explicit project-scope decision.
- Treat activation directions as experimental hypotheses requiring held-out and causal tests, not semantic proof.
- Describe operational traces as observed execution provenance. Describe reference certificates as fixed-input machine-checked equivalence, and bounded-domain certificates as exhaustive only over their declared canonical states; neither is a universal proof or independent primitive-kernel verification.
- Describe the typed Gemma IR as a complete structural program at its declared primitive boundary. A fixed-input IR certificate may establish bit-exact prediction against pinned Hugging Face eager execution, but the current interpreter shares PyTorch primitives with the comparator and does not establish independent bit-level primitive semantics, SDPA equivalence, fused-kernel equivalence, or unrestricted-input correctness. Independent coordinate-oracle cases for indexing/data movement, exact-rational finite-bfloat16 `ADD`/`MUL`/`SCALE` cases, and reduction-candidate comparisons are bounded conformance or characterization evidence, not unrestricted-domain or hardware proofs. A reduction candidate matching some vectors, a controlled Gemma-shape launch matching an attested kernel symbol, an exhaustive three-term K16 retention rule, finite signed-magnitude thresholds, or a unique all-matching candidate within a declared search grid do not establish complete deployed reduction order, CUTLASS correspondence, numeric accumulator mapping, magnitude generalization, recorded-value identity, or per-invocation correspondence; the primitive gate must remain false while any reached floating-point opcode, reduction order, special input, or backend correspondence is unresolved.
- Limit universal-proof claims to the exact SMT formulas, widths, domains, and explicit premises recorded in each obligation. Describe CUDA manifests as launch and binary provenance and SASS equations as proposed subset semantics, not hardware or instruction-level verification. Distinct-kernel suite coverage means one attested invocation per recorded symbol, not every invocation. Module NVTX bindings identify enclosing framework ranges and boundary tensors. CUPTI launch-parameter matches establish equal pointer-sized values only; do not call them typed signatures, access-direction proofs, or complete CUDA argument semantics.
- Never allow an LLM to create or modify approved policy rules, coefficients, limits, or execution authority.
- Keep model checkpoints and full generated traces, profiler reports, cubins, and tensor-rich artifacts out of Git. Compact reproducible certificates and summaries under `results/` are checked evidence and may be committed.
- Install `.[gemma]` before full operational-semantics verification and `.[proof]` before SMT verification; optional tests skip when their dependencies are absent.
- Run `python -m unittest discover -s tests -v` after code changes.
- Run `python -m bioprocess_runtime suite` to verify built-in scenarios.
- Run `python -m compileall -q bioprocess_runtime tests` for syntax verification.
- Inspect saved copy-drift failure targets without model inference using `python -m bioprocess_runtime.gemma_failure_targets`; `--output` requires a new path. Run its standard-library-only tests with `python -m unittest discover -s tests -p test_gemma_failure_targets.py -v`. This is exploratory inspection of existing evidence, not a new numerical or causal validation.
- Check the declared S=30 execution profile against frozen artifacts and pinned source literals using `python -m bioprocess_runtime.gemma_execution_profile`; `--output` requires a new path and exits nonzero if any check fails. Tests: `python -m unittest discover -s tests -p test_gemma_execution_profile.py -v`. A profile that has produced frozen evidence is never edited in place; other sequence lengths, positions, decoding modes, or backends require a new profile ID and new evidence.
- Recover copy/drift prompt token IDs and effective decode/cache settings offline using `python -m bioprocess_runtime.gemma_prompt_tokenization --model-dir <dir>`; the directory must contain the pinned tokenizer/config assets (hashes verified) and `--output` requires a new path. Needs `tokenizers==0.21.4` and `jinja2`; tests skip when absent: `python -m unittest discover -s tests -p test_gemma_prompt_tokenization.py -v`. The saved probe decoded through the hybrid KV cache (sliding-512 except layers 5/11/17), not the full-recompute independent path; equivalence is unestablished.
- CPU attention evidence (`gemma3_270m_copy_drift_attention_capture_v1.json`, `gemma3_270m_copy_drift_attention_ablation_v1.json`; harnesses `artifacts/gemma_copy_drift_attention_capture_v1.py` and `artifacts/gemma_copy_drift_attention_ablation_v1.py`) is decode-path intervention evidence on CPU: post-softmax weights are zeroed for selected layer/head/KV positions at the decision step's last query row without renormalization, which attenuates head output magnitude as well as direction. Attention mass is localization evidence, not causal proof; an ablation flip shows necessity under this intervention semantics on this backend only. Findings so far: full-attention layers 5/11 carry the value-token retrieval; c12's wrong '7' flips to the correct '3' when L5H1's attention to the row-1 value span is ablated, while asked-span ablation strengthens '7' — consistent with head-level positional copying; c16's wrong digit is more distributed and no single-head ablation flips it.
- A source-only checkout lacks `artifacts/gemma270m_architecture_manifest.json`; `test_gemma_ir.GemmaIrTests.setUpClass` requires that original artifact and skips without it. The `test_gemma_ir_primitives` gate tests similarly skip when the committed backend-binding evidence does not satisfy the current verifier. Installing optional dependencies alone does not supply the artifact.
- CPU-backend Gemma evidence (`gemma3_270m_copy_drift_cpu_replay_v1.json`, `gemma3_270m_copy_drift_counterfactual_v1.json`, protocol `gemma3_270m_copy_drift_counterfactual_protocol_v1.md`, sealed cases `gemma3_270m_copy_drift_counterfactual_cases_v1.json`, harnesses `artifacts/gemma_copy_drift_cpu_replay_v1.py` and `artifacts/gemma_copy_drift_counterfactual_v1.py`) is new-backend evidence: decisions and top-five structure only, never bitwise CUDA score equality, never fresh confirmatory holdouts. Findings so far: all five recorded digit substitutions reproduce on CPU under hybrid-cache and full-recompute paths with identical CPU logits; counterfactuals show positional (first-row) binding in the dash-list format and key/entity binding in the JSON format.
- Do not edit numerical/evidence source files while prediction, acquisition, or replay processes are active. Attention-score plans pin the entire score module's source bytes; source changes (including line-ending conversions) require a new versioned plan and verification, not an in-place artifact update.
- WSL2 Ubuntu 24.04 has CUDA Toolkit 12.9.2, PyTorch 2.7.1+cu128 in `/opt/bioprocess-venv`, and NVBit 1.8 at `/opt/nvbit-1.8`; CUDA paths load from `/etc/profile.d/cuda.sh`. Baseline and targeted predicate/register instrumentation work on the RTX 4090, but forwarded driver 616.56 exceeds NVBit's documented 575.xx ceiling, so treat this support as experimental and keep timeouts on instrumented runs. The Linux memory-efficient attention kernel retains all selected offsets and its ten runtime-loaded selected instruction encodings match the attested Windows instructions, but the extracted Linux cubin and full static normalized SASS hashes differ; treat this as selected-instruction correspondence only and never import incomplete observations into the existing exact-cubin bundle.
- Synthetic NVBit baseline/replay writes pass across two CTAs/64 lanes for class-0/1/2 `IADD3` and class-0/1 two-source `LEA`, with configurable launches, linear CTA/thread indexing, missing-baseline no-write behavior, and restored outputs. Isolated matching-runtime Q/K/V low and high `LEA` pairs each pass classes 0/1 over three controlled launches and 1,536 lanes per class with identical attention outputs; cross-run matched-vector recomposition passes. Query and key same-launch sequential pairing pass classes 0/1 over three controlled launches. Value low/P2R/high pairing also passes when P2R destination is captured and immediately restored; P2R output is invariant to P6 only for observed vectors, not by authoritative mask semantics. Keep the full Gemma forward and output pairs write-disabled until exact-cubin evidence, independent reproduction, dynamic-occurrence-indexed restoration, and full qualification pass; output reachability alone is insufficient because output offsets can execute repeatedly within one thread. NVBit does not expose arbitrary original-instruction duplication.
